# Printing arrays in Drift

Drift has three distinct output paths for arrays, depending on whether the user wants to print a single value, a selection of values, or the full structured contents of an array.

## 1. Printing scalars

Scalar values are printed directly.

```drift
var x = 42
say x
```

This prints:

```text
42
```

## 2. Printing a single array element

An array element is printed by using explicit indices.

```drift
var arr[2][2] = {{1,2}{3,4}}
say arr[0][1]
```

This prints:

```text
2
```

The number of indices must match the array rank. For example, a 2D array requires two indices, a 3D array requires three, and so on.

## 3. Printing a selection

A selection prints one or more values from an array. It is written with `select(...)` and each tuple must match the array rank.

```drift
var arr[2][2] = {{1,2}{3,4}}
say arr.select((0,1))
```

This prints:

```text
2
```

If the selection contains multiple coordinates, the interpreter prints each selected value in order, separated by spaces.

```drift
var arr[2][2] = {{1,2}{3,4}}
say arr.select((0,1), (1,0))
```

This prints:

```text
2 3
```

## 4. Printing a full array value

A full array is not printed by a bare variable reference. The interpreter requires an explicit array access form.

The supported forms are:

- a single element access such as `arr[0][1]`
- a selection such as `arr.select((0,1), (1,0))`
- an array-valued declaration such as `var values[] = ...`

### Full-array output via a declaration

```drift
var arr[2][2] = {{1,2}{3,4}}
var values[] = arr.select((0,1), (1,0))
say values
```

The declaration `var values[] = ...` requests an array result. The output is printed in a structured form based on the array shape.

### Output format for full arrays

The current formatter prints arrays in a row-wise, nested layout:

```drift
var arr[2][2] = {{1,2}{3,4}}
var values[] = arr.select((0,1), (1,0))
say values
```

The output is rendered as:

```text
2 3
```

For multi-dimensional arrays, the formatter prints nested levels with line breaks between major blocks.

## 5. Current limitations

At the moment, the printer supports:

- scalars
- single-element access
- selection output
- structured printing of array values produced by array-valued declarations

It does not currently support printing a bare array variable directly with `say arr`. Doing so still triggers the explicit-access rule.

## 6. Implementation notes

The current runtime behavior is implemented through three printer paths:

- element printing for indexed access
- selection printing for `select(...)`
- recursive structured printing for full array values

This is the behavior available in the current interpreter.
