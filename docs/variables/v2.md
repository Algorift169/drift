# Variables and arrays in Drift

Drift variables can hold scalars, arrays, or values produced by array access expressions. The current language supports several ways to create arrays, including fixed-size declarations, dynamic declarations, and array-valued results from selections.

## 1. Array declarations

Arrays are declared with square brackets after the variable name.

```drift
var arr[2][2][2] = {{1,2}{3,4}}{{5,6}{7,8}}
```

The bracket list declares the rank of the array. Each dimension is fixed at declaration time.

### Fixed-size declaration

A fixed-size declaration uses explicit dimension sizes:

```drift
var arr[2][2] = {{1,2}{3,4}}
```

This creates a 2D array with two rows and two columns.

### Dynamic declaration

A dynamic declaration uses empty brackets `[]` for one or more dimensions.

```drift
var arr[][] = {{1,2}{3,4}}
```

The interpreter infers the missing dimension sizes from the initializer structure. This works for multi-dimensional arrays as well, including 3D and 4D forms.

```drift
var arr[][][] = {{{1,2},{3,4}},{{5,6},{7,8}}}
```

In this case, the parser infers the nested shape from the initializer blocks.

## 2. Array initialization from literals

Arrays can be initialized from nested literal braces.

### Fixed-size initializer

```drift
var arr[2][2] = {{1,2}{3,4}}
```

The initializer must match the declared dimensions exactly.

### Dynamic initializer

```drift
var arr[][] = {{1,2},{3,4}}
```

When a dimension is omitted, the parser infers its size from the nested initializer structure. The initializer must still be consistent across all branches.

### Multi-dimensional dynamic initializer

```drift
var arr[][][] = {{{1,2},{3,4}},{{5,6},{7,8}}}
```

This form is accepted when each nested block has the same shape.

## 3. Array creation from selections

A `select()` expression can produce one or more values. When the result is assigned to a variable, the variable may either be scalar or array-valued.

### Scalar selection

If the declaration is scalar, the selection must resolve to exactly one value.

```drift
var value = arr.select((0,1,1))
```

### Array-valued selection

If the selection returns multiple values, the declaration must explicitly request an array result by using `[]`.

```drift
var values[] = arr.select((0,1,1), (0,1,2))
```

This creates an array from the selected values.

## 4. Array creation from array access expressions

Array access expressions can also be used to create values for declarations. The current runtime supports storing an array expression result into a variable with explicit array syntax.

```drift
var arr[2][2] = {{1,2}{3,4}}
var values[] = arr.select((0,1), (1,0))
```

The `[]` in the declaration tells the parser and interpreter that the result is intended to be an array rather than a single scalar.

## 5. Shape rules

The current array creation logic uses the following rules:

- Fixed-size declarations use the written bracket sizes directly.
- Dynamic declarations infer missing sizes from nested initializer blocks.
- Selection-based declarations create an array when the declaration uses `[]`.
- The initializer must be structurally consistent; otherwise the parser reports an inconsistent nested array dimensions error.

## 6. Current limitations

The current implementation supports:

- fixed-size arrays
- dynamic arrays with omitted dimensions
- multi-dimensional initializer inference
- selection-based array creation
- explicit array-valued declarations with `[]`

It does not yet support full runtime mutation or richer array operations beyond creation, selection, and printing.
